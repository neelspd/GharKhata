# Contributing to GharKhata

Thank you for your interest in contributing to GharKhata.

GharKhata is a personal pet project and portfolio project, but contributions, suggestions, discussions, and design ideas are welcome.

---

## Project Intent

The goal of GharKhata is to digitize the traditional Indian household diary/khata system.

The project should stay focused on:

- Household ledger workflows
- Vendor-wise monthly settlement
- Daily calendar-based entries
- Recurring household bills
- Simple and friendly UX
- Practical Indian household use cases

This project should not become a generic expense tracker unless the feature clearly supports household ledger workflows.

---

## Ways to Contribute

You can contribute by:

- Reporting bugs
- Suggesting features
- Improving documentation
- Proposing UI/UX improvements
- Adding backend modules
- Adding frontend components
- Improving tests
- Improving accessibility
- Reviewing architecture decisions

---

## Before Opening a Pull Request

Please make sure:

1. Your change has a clear purpose.
2. Your code is readable and reasonably documented.
3. You have tested your changes locally where possible.
4. Your change does not introduce unrelated refactors.
5. Your change aligns with the household ledger product direction.

---

## Suggested Development Workflow

1. Fork the repository.
2. Create a feature branch.

```bash
git checkout -b feature/your-feature-name
```

3. Make your changes.
4. Commit with a clear message.

```bash
git commit -m "Add vendor settlement summary"
```

5. Push your branch.

```bash
git push origin feature/your-feature-name
```

6. Open a pull request.

---

## Product Principles

### 1. Diary first, accounting second

The UX should feel like a digital household diary, not enterprise accounting software.

### 2. Fast daily entry

Adding a daily entry should be quick and low-friction.

### 3. Vendor-wise clarity

Users should always be able to answer:

> How much do I owe this person or vendor?

### 4. Recurring by default, exceptions when needed

Daily milk, newspaper, and monthly salaries should not require repetitive manual entry.

### 5. Keep it understandable

Avoid exposing complex accounting terms unless absolutely necessary.
